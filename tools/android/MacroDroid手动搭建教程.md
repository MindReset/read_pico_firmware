# MacroDroid 手动搭建「复制即推」傻瓜教程

> 适用：ReadPico 墨水屏 + 安卓手机（无 Google Play 也能用，荣耀 MagicOS / Android 16 已验证路径）。
> 目标：在手机上复制一段文字 → 自动推到墨水屏并开书，全程不用电脑。
> 时间：首次搭建约 10 分钟，之后复制即用。

## 0. 先回答你的问题：ReadPicoPush.macro 为什么导入失败

不是版本兼容问题——**这个文件在任何 MacroDroid 版本都导不进**。三层原因（均有官方文档实证）：

| # | 问题 | 说明 |
|---|------|------|
| 1 | **格式不对** | MacroDroid 的宏导入格式是 **JSON**，而我们给的是手写 XML。导入器第一关就过不去 |
| 2 | **没有这个动作** | MacroDroid **没有原生 BLE GATT 写入动作**（官方动作清单里只有蓝牙开关/共享网络类），XML 里写的 `<BluetoothLEAction>` 是无定义的 |
| 3 | **脚本也跑不动** | 就算前两条都过了，里面 JavaScript 动作用的 `TextEncoder` 在 MacroDroid 的 Rhino 引擎里不存在，一运行就报错 |

**结论**：不要找"兼容版本"了，没有。正解就是本教程——用 MacroDroid 的 **Java Code（Java 代码）动作** + 我们写好的 `ReadPicoPush.bsh` 脚本手动搭一个宏。这是当前版本唯一可行的全自动推送通道（脚本已在沙箱里用 BeanShell 解释器完整跑通：帧字节与固件协议参考实现逐字节一致）。

## 1. 准备工作（3 分钟）

1. **安装 MacroDroid**：荣耀应用市场搜 "MacroDroid"，或去官网 macrodroid.com 下 apk 直接装（不需要 Google Play）。免费版限 5 个宏，本教程只用 1 个，免费版足够。
2. **墨水屏就绪**：固件是 gen12 或更新版本；在设备上开启「手机推送」，屏幕/日志会出现广播名 **PicoPush-XXXX**（XXXX 是四位十六进制，记不记都行，脚本会自己读）。
3. **手机蓝牙打开**，设备与手机保持 1 米内。
4. **拿到脚本文件**：`ReadPicoPush.bsh`（和本教程同目录，交付 zip 的 `android-tools/` 里也有）。用手机文件管理器找到它，**先用文本编辑器打开确认能看全文**（推荐 QuickEdit、MT 管理器等任意文本编辑器；不要用 Word/WPS，会丢格式）。

---

## 2. 三个必须的授权（不做的话一定失败，荣耀手机重点看第 3 条）

### 2.1 蓝牙 / 附近设备权限

系统设置 → 应用 → MacroDroid → 权限 → 打开「附近的设备」和「蓝牙」（Android 12+ 把蓝牙权限拆成了这两项，都要给）。
首次运行宏时系统也可能弹窗，选「允许」。

### 2.2 无障碍服务（Android 10+ 读剪贴板的唯一免电脑通道）

Google 从 Android 10 起禁止后台应用读剪贴板。MacroDroid 的剪贴板触发器靠无障碍服务拿到复制内容：

系统设置 → 辅助功能（无障碍）→ 已下载的服务 → **MacroDroid（UI Interaction）** → 开启。

> MacroDroid 里第一次添加剪贴板触发器时通常会自动弹窗引导你去开，跟着点就行。

### 2.3 保活三件套（荣耀/华为系手机杀后台很凶，不做的话宏时灵时不灵）

| 设置项 | 路径（各版本略有差异） | 设为 |
|--------|----------------------|------|
| 电池优化 | 设置 → 应用 → MacroDroid → 电池 | **无限制** |
| 应用启动管理 | 设置 → 应用 → 应用启动管理 → MacroDroid → 手动管理 | 允许**自启动** + **后台活动** |
| 多任务加锁 | 上滑多任务卡片，下拉 MacroDroid 卡片出现锁头 | **加锁** |
| 通知 | 设置 → 通知 → MacroDroid | 允许（常驻通知是保活手段） |

## 3. 建变量（30 秒）

MacroDroid 主界面 → **变量**（Variables）→ 右下角 **+** → 新建**字符串**变量，命名：

```
pico_result
```

（用来接脚本的返回结果。愿意留排错日志的话再建一个同类型的 `pico_log`。）

---

## 4. 点击级建宏（5 分钟）

### 4.1 新建宏，选触发器

1. MacroDroid 主界面点 **+**（或「添加宏」）
2. 触发器列表里找到 **剪贴板变化**（Clipboard Change，可在「界面/系统」分类里翻）→ 点它
3. 配置项 **「剪贴板文本」留空**（空 = 任何剪贴板变化都触发）→ 确认
4. 直接进入动作配置（**不要加约束**，直接下一步）

### 4.2 加动作 1：Java Code（核心）

1. 点 **添加动作**（+）
2. 动作列表里找 **Java Code**（Java 代码，在「脚本 / Scripting」分类下；该功能官方标记为实验性，但可正常用）
   - **找不到？** 说明 MacroDroid 版本太旧，去官网更新到最新版再试
3. 点**代码编辑器**，把 `ReadPicoPush.bsh` 的**全文**粘贴进去（在文本编辑器里全选 → 复制 → 在这里全选粘贴）
   - ⚠️ 必须完整粘贴，从第一行 `/* ====...` 到最后一行 `result;`。漏行会报错
   - ⚠️ 不要手动"整理"代码，脚本是刻意按老语法写的
4. 回到配置页，确认这几项：
   - **后台线程运行**：保持**开启**（默认就是开的；脚本要等蓝牙回调，必须后台线程）
   - **输出变量**：填 `pico_result`
   - **控制台输出字符串变量**（可选）：填 `pico_log`
5. 保存动作

### 4.3 加动作 2：Toast 提示

1. 再点 **添加动作** → 找 **Toast 提示**（Toast）
2. 消息框填：`{v=pico_result}`
3. 时长选**长**（Long）→ 保存

### 4.4 保存宏

点下一步 → 给宏起名 **ReadPicoPush** → 保存。回到宏列表，确认开关是**打开**状态。

---

## 5. 测试（1 分钟）

1. 墨水屏：开启「手机推送」（进入武装窗口，会开始广播 PicoPush-XXXX）
2. 手机：**复制任意一段文字**（微信/浏览器/备忘录里复制都行）
3. 等 3–10 秒：
   - 手机弹出 Toast：**「推送成功：设备已校验并开书（N 字节 / M 包）」**
   - 墨水屏：CRC 校验通过后自动打开这本书
4. 以后每次复制文字都是这个流程。窗口过期了就再去设备上点一次「手机推送」。

## 6. 排错表（按 Toast 提示对号入座）

| Toast 提示 | 原因 | 处理 |
|-----------|------|------|
| 失败：剪贴板为空 | 无障碍服务没开；或个别机型触发器没带上文字 | ① 检查 2.2 无障碍服务；② 在 Java Code 动作**前面**加一个「剪贴板刷新 / Clipboard Refresh」动作（剪贴板分类），再试 |
| 失败：12 秒内未发现 PicoPush-XXXX 广播 | 设备没进武装窗口 / 蓝牙没开 / 太远 / 少数机型要定位权限 | 设备上重开「手机推送」；靠近；开系统定位开关并给 MacroDroid 位置权限 |
| 失败：BLE 扫描启动被拒 / 缺少蓝牙权限 | 附近设备/蓝牙权限没给全 | 按 2.1 补权限，然后**重跑宏**（权限是运行时检查的） |
| 设备拒绝 BEGIN：设备未处于接收窗口（错误码1） | 复制时设备不在武装窗口（窗口超时或没开） | 设备上重新开启「手机推送」再复制 |
| 设备拒绝 BEGIN：CRC32 校验不符（错误码4） | 极罕见：链路干扰导致帧损坏 | 直接重试；反复出现请反馈（附 `pico_log`） |
| 失败：MTU 协商结果异常 | 设备固件过旧（< gen12 的 ATT 配置） | 升级固件 |
| 宏完全不触发（复制没反应） | 被杀后台 / 剪贴板触发器没配好 | 按 2.3 做保活；确认触发器「剪贴板文本」是空的 |
| 想看详细过程 | — | 排错时把宏里 Java Code 的「控制台输出变量」填上 `pico_log`，跑完去 变量 页看 `pico_log` 内容（含扫描/连接/MTU/每包进度） |

**通用绝招**：任何诡异问题，先「重开手机推送 → 靠近 → 再复制一次」。推送窗口有超时，超时后的第一次复制必然失败。

## 7. 备选路径（自动化之外）

| 方案 | 适合场景 | 说明 |
|------|---------|------|
| **nRF Connect 手动推送** | 验收/排障基准，**最可靠** | 不需要任何自动化，见 `nrf-connect-manual.md`。任何自动化失败时都用它确认链路本身是好的 |
| **ADB logcat 剪贴板检测** | 有电脑、剪贴板触发器不稳时 | 在 MacroDroid 触发器里勾选 "Use logcat detection (ADB Hack)"，电脑执行 `adb shell pm grant com.arlosoft.macrodroid android.permission.READ_LOGS` |
| **M2 极简 APK** | 长期正解 | 原生 BLE 推送 App，无剪贴板权限坑、无保活坑，规划中 |

## 8. 高阶：脚本里唯一可能要改的地方

`ReadPicoPush.bsh` 顶部有一个常量：

```java
int    BODY_TYPE      = 0;       /* 0=纯文本 3=URL 4=单词卡 */
```

- `0`（默认）：复制文字 → 推全书
- `4`：复制一个单词 → 设备弹词典卡片（需要设备装有词典）
- `3`：URL（设备端抓取是 M1.5 功能，实验性）

改完保存宏即可，其他都不要动。帧格式、CRC、UUID 全部与固件 `push_proto.h` 冻结一致，**改协议部分会让推送失败**。

## 附：脚本可靠性说明（给较真的人）

`ReadPicoPush.bsh` 不是"看起来对"——它在 BeanShell 解释器 + Android API 模拟环境里做过完整流程测试：主路径/多分片/单词卡/错误码 1、4/权限拒绝/空剪贴板/扫描超时全部通过，且 BEGIN/DATA/END 三種帧与固件侧参考实现 `push_pico.py` **逐字节一致**（含 CRC32 与中文标题截断）。测试中修掉了一个真机必炸的坑：BeanShell 给 `byte` 数组元素赋 int 字面量会抛 `ArrayStoreException`，脚本内所有字节赋值均已显式强转。
